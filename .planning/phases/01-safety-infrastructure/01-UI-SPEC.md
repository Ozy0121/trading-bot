| Property | Value |

## Component Inventory

New UI components required by BRACKET-04 and BRACKET-05. All must match existing glassmorphism patterns.

### 1. Bracket Status Badge (BRACKET-04)

Inline badge added to each row in the positions table showing bracket order status.

```
Pattern: .badge class + variant modifier
States:
  Protected  → green badge, text "PROTECTED", green border glow
  Unprotected → red badge, text "NO STOP-LOSS", red border, pulsing warning
  Pending    → yellow badge, text "PLACING…"
```

Exact CSS to add:
```css
.badge-protected   { background: rgba(74,222,128,.1); color: var(--green); border: 1px solid rgba(74,222,128,.15); box-shadow: 0 0 12px rgba(74,222,128,.08); }
.badge-unprotected { background: rgba(232,116,97,.1); color: var(--red); border: 1px solid rgba(232,116,97,.2); animation: pulse 2s ease-in-out infinite; }
.badge-sl-pending  { background: rgba(212,168,67,.08); color: var(--yellow); border: 1px solid rgba(212,168,67,.15); }
```

### 2. Stop-Loss / Take-Profit Price Columns (BRACKET-04)

Two new columns added to the existing `.positions-table` in the Positions tab.

```
Column: Stop-Loss    → right-aligned, JetBrains Mono 12px 600, color var(--red)
Column: Take-Profit  → right-aligned, JetBrains Mono 12px 600, color var(--green)
Column: Status       → right-aligned, contains Bracket Status Badge
```

Format: prices displayed as `$XX.XX`. If not set: display `—` in `var(--muted)`.

### 3. Exit Settings Panel (BRACKET-05)

New compact panel (matches `.panel` class) added to the Controls tab for adjusting stop-loss and take-profit percentages at runtime.

```
Layout: .panel with panel-header "Exit Settings"
Contents:
  - Stop-Loss %: labeled input, range 1–10%, step 0.5%
  - Take-Profit %: labeled input, range 2–20%, step 0.5%
  - [Apply Changes] button — primary action
  - Confirmation feedback: inline status message below button
```

Input style: matches existing `.tb-btn` pattern for visual consistency — bordered, glass background, Inter 12px.

Apply button: matches existing `.btn-danger` pill shape but uses blue/teal gradient (not red) to indicate a save action, not a destructive one:
```css
#apply-exits-btn {
  background: linear-gradient(135deg, #2d5a47, #4d8a6f);
  color: #fff; border-radius: var(--radius-pill);
  box-shadow: 0 6px 20px rgba(77,138,111,.25), inset 0 1px 0 rgba(255,255,255,.08);
}
```

### 4. Shutdown Stop-Loss Warning (BRACKET-03)

Modal overlay (matches existing `#start-overlay` pattern) shown on bot shutdown if any positions lack server-side stop-losses.

```
Trigger: POST /api/stop → missing bracket orders detected
Surface: fixed overlay, rgba(10,16,14,.92) backdrop-filter:blur(12px)
Content:
  - Warning icon row (unicode ⚠)
  - Heading: "Stop Without Protection?" (16px Inter 600)
  - Body: lists each unprotected symbol
  - [Place Stop-Losses First] button → teal gradient, pill shape
  - [Stop Bot Anyway] button → red gradient, pill shape (destructive)
```

## Interaction Contracts

### Bracket Order Placement Flow (BRACKET-01)

After every stock buy:
1. Buy order submits → existing fill poll runs (10s timeout, SAFE-03)
2. On confirmed fill: bracket order placed immediately
3. Position row updates: Status column flashes `.flash-green`, badge changes to `PLACING…` (yellow)
4. After bracket confirmed on Alpaca: badge updates to `PROTECTED` (green)
5. If bracket placement fails: badge shows `NO STOP-LOSS` (red, pulsing), log item added with event `BRACKET_FAILED`

### Settings Apply Flow (BRACKET-05)

1. User edits Stop-Loss % or Take-Profit % inputs
2. Clicks [Apply Changes]
3. Button shows `Applying…` disabled state (100ms debounce)
4. POST to `/api/config/exits` with new percentages
5. On success: inline message "Settings saved. New positions will use updated levels." (green text, 3s auto-dismiss)
6. On failure: inline message "Failed to save. Check bot logs." (red text, persists until next attempt)
7. Existing open positions: separately note "Existing bracket orders are not modified — only future trades use new levels."

### Startup Protection Check (BRACKET-02)

On bot start:
1. Bot checks all positions for active stop-losses (backend)
2. If missing: automatic recreation (no user prompt, logs the event)
3. Dashboard reflects updated status without page reload (polling picks up new state)
4. Log item added with event `BRACKET_RECREATED` for each recreated order

### Fill Status Display (SAFE-03)

During order polling window (up to 10s):
1. Position row shows `FILLING…` in monospace yellow
2. If partial fill: row shows filled qty vs ordered qty, e.g. `8 / 10 shares`
3. If rejected: log item added with event `ORDER_REJECTED`, row cleared, no position shown
4. If partial accepted: row shows actual filled qty, bracket placed for that qty

## States Required per UI Surface

### Positions Table (Positions Tab)

| State | Trigger | Visual |
|-------|---------|--------|
| No positions | Empty position list from API | `#pos-empty` row: "No Open Positions" centered, `var(--muted)` |
| Position with bracket | Active stop-loss confirmed on Alpaca | `PROTECTED` green badge + green stop-loss and take-profit price columns |
| Position without bracket | Missing stop-loss detected | `NO STOP-LOSS` red pulsing badge + `—` in price columns |
| Position placing bracket | Bracket order submitted, awaiting confirmation | `PLACING...` yellow badge |
| Positive P&L | unrealized_pl > 0 | `.c-green` class on P&L cell |
| Negative P&L | unrealized_pl < 0 | `.c-red` class on P&L cell |

### Exit Settings Panel (Controls Tab)

| State | Trigger | Visual |
|-------|---------|--------|
| Default | Page load | Inputs show current config values; no message |
| Dirty | User edited an input | No visual change — apply on button click only |
| Saving | Button clicked | Button disabled, text "Applying..." |
| Saved | API 200 | Green inline message, 3s auto-dismiss |
| Error | API non-200 | Red inline message, persists |
