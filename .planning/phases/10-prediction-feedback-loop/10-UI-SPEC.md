## Color

All tokens sourced from `:root` in `templates/index.html` lines 13–53. Use CSS variables exclusively — never hardcode hex in new HTML.

| Role | CSS Variable | Hex | Usage |
|------|-------------|-----|-------|
| Dominant (60%) | `var(--bg)` | `#0e0e0e` | Page background |
| Secondary (30%) | `var(--surface-low)` / `var(--surface)` | `#131313` / `#191919` | Cards, sidebar, chart cards, table backgrounds |
| Accent (10%) | `var(--primary)` | `#c8c8b0` | See reserved-for list below |
| Destructive | `var(--error)` | `#ed7f64` | Error states, destructive indicators only |

**Accent (`var(--primary)`) is reserved for:**
- Active sidebar nav indicator (left border + text)
- Positive accuracy percentage when above 60% threshold
- The live dot pulse animation in the logo
- Weight value when new weight is higher than old weight (improvement indicator)
- The progress bar fill in the accuracy scorecard

**Semantic colors for new Phase 10 elements:**

| State | Token | Usage |
|-------|-------|-------|
| Correct / win | `#66bb6a` (inline, matches existing scorecard) | Signal accuracy above 60%, correct prediction count |
| Warning / pending | `#ffa726` (inline, matches existing scorecard) | Pending predictions, accuracy 40-60%, signals with < 10 samples |
| Wrong / error | `var(--error)` `#ed7f64` | Signal accuracy below 40%, incorrect prediction count |
| Neutral / muted | `var(--outline)` `#757575` | Labels, timestamps, secondary text, default weights |

Note: The existing scorecard already uses `#66bb6a`, `#ffa726`, and `#ef5350` inline (not via CSS variable). Phase 10 must match these exact values for visual consistency with the existing accuracy display.

## Layout Contract

### Accuracy Banner (D-10)
- Location: Inside existing `#scorecard-section` `.chart-card`, above the existing 6-stat grid
- Always visible (no collapse, no toggle)
- Format: `"Last {N} resolved predictions: {X} correct ({Y}%)"` — plain text, stat values bolded in Space Grotesk 700 at 20px inline
- Updates: On page load via `loadAccuracyBanner()`, on manual recalibration trigger, on CHECK ACCURACY click

### Per-Signal Stats Section (D-11)
- Location: New collapsible `<details>` element below the existing scorecard bar chart row, inside `#scorecard-section`
- Collapsed by default; `<summary>` label: "SIGNAL ACCURACY BREAKDOWN" in Space Grotesk 10px 600 uppercase
- Contains:
  1. Per-signal accuracy table (8 rows: rsi2, ibs, consec_down, bb_lower, volume_profile, order_flow, amt_state, volume_spike)
  2. Accuracy trend sparkline (Chart.js line chart, 180px tall, 100% wide)
  3. Calibrated weights vs defaults comparison rows

### Per-Signal Table Layout

| Column | Content | Width |
|--------|---------|-------|
| Signal | Signal name in Space Grotesk 10px uppercase | 25% |
| Samples | Integer count, `var(--outline)` if < 10 | 15% |
| Accuracy | Percentage with color coding | 20% |
| Mini-bar | 6px progress bar, colored by accuracy | 25% |
| Weight (default) | e.g. "4.0" in `var(--outline)` | 7.5% |
| Weight (calibrated) | e.g. "4.6" in `var(--primary)` if higher, `var(--error)` if lower | 7.5% |

Row color rules:
- Accuracy >= 60%: `#66bb6a` — matching existing scorecard
- Accuracy 40-59%: `#ffa726`
- Accuracy < 40%: `var(--error)`
- Sample count < 10: show "(low sample)" in `var(--outline)` 10px after value; do not color-code accuracy — show `—` instead

### Recalibration Metadata (D-12)
- Location: Below per-signal table, inside the same `<details>` collapsible
- Format: `"Last recalibrated: Sunday, May 25 at 12:00 AM ET"` — 11px Space Grotesk, `var(--outline)`
- If never recalibrated: `"Not yet recalibrated — runs Sunday at midnight ET"`
- Weight changes list: each change on its own line, format: `"rsi2: 4.0 → 4.6"` with arrow, old in `var(--outline)`, new colored by direction

### Accuracy Trend Sparkline (D-11, Claude's Discretion)
- Chart type: Line chart (Chart.js, already loaded)
- Height: 120px
- Width: 100% of container
- X-axis: Dates (rolling 30-day window, weekly ticks)
- Y-axis: Accuracy % (0-100 range, no axis labels — just gridlines)
- Line color: `var(--primary)` `#c8c8b0`
- Fill: rgba of primary at 0.08 opacity
- No legend, no tooltips except hover dot
- Grid color: `var(--outline-variant)` `#484848`
- Point radius: 3px on hover only

## Interaction Contract

### Manual Recalibrate Trigger
- Button: `.tb-btn` labeled `RECALIBRATE NOW` in the `.chart-card-header` of the prediction accuracy section
- On click: POST to `/api/prediction-log/recalibrate`
- Loading state: Button disabled, icon spins (use `animation: spin 1s linear infinite` on the `refresh` Material Symbol)
- On success: Re-fetch accuracy banner data, re-render per-signal table, show success toast
- On skip (< 20 predictions): Show warning toast with skipped reason, do not re-render table
- On error: Show error toast, re-enable button

### Accuracy Banner Auto-Update
- Load on page init (add to existing `initDashboard()` call chain)
- Refresh after CHECK ACCURACY completes (extend existing `checkLiveAccuracy()` callback)
- Refresh after RECALIBRATE NOW completes
- No polling interval — event-driven only

### Per-Signal Table Load
- Fetched lazily on `<details>` expand (first open triggers `fetch('/api/prediction-log/signal-accuracy')`)
- Subsequent opens use cached data (refresh on recalibration only)
- Loading state: spinner row spanning all columns

### Weight Display
- Default weights are hardcoded in JS from known defaults: `{rsi2: 4.0, ibs: 3.5, consec_down: 3.0, bb_lower: 3.5, volume_profile: 1.5, order_flow: 1.0, amt_state: 1.0, volume_spike: 1.5}`
- Calibrated weights fetched from `/api/prediction-log/signal-weights`
- If no calibrated weights file exists: show default in both columns, label calibrated column as `DEFAULT` with a `(not yet calibrated)` note
